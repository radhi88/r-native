# Prompt - ورشة بناء بتدقيق خصمي

**Summary:** نمط ورشة عمل: بنّاؤون (builders) كلٌّ على ملفات منفصلة كي لا يتصادموا، ثم مدقّق خصمي (adversarial verifier) وظيفته الوحيدة أن **يدحض** كل ادعاء أمان بأرقام الأسطر. الادعاء غير المدحوض فقط يُعتمد. [[high-value]] [[evergreen]]

## الغرض (Purpose)
البنّاء يحب مخلوقه ويصدّق ادعاءاته («يوجد demo guard»، «الستوب إلزامي»، «اللوت مسقوف»). في نظام يضع أوامر حقيقية على MT5، الادعاء غير المُختبَر = ثغرة. المدقّق الخصمي كان سيلتقط مضاعف اللوت x15 المخفي قبل أن يصل للتشغيل (انظر [[Decision - 2026-07-07 - إبطال مضاعف اللوت x15]]).

## نص البرومبت (The Prompt)
```
نظّم ورشة بناء [FEATURE] بثلاثة أدوار:

1. BUILDERS (بالتوازي): كل بنّاء يملك ملفات منفصلة تماماً —
   ممنوع أن يلمس اثنان الملف نفسه (لا تصادم merge، لا استيراد دائري).
   كل بنّاء يسلّم مع كوده قائمة "ادعاءات أمان" صريحة:
   (demo-only guard، سقف لوت، ستوب إلزامي، تجميد يومي، atomic write...).

2. VERIFIER (خصم): لكل ادعاء أمان، حاول أن تدحضه:
   - اقرأ الكود الفعلي واذكر رقم السطر الذي يثبت أو ينقض الادعاء.
   - ابحث عن مسار تنفيذ يتجاوز الحارس (exception يبتلع الفحص؟
     config يعطّله؟ ضرب/تقريب يضخّم اللوت؟).
   - إن لم تجد نقضاً: اكتب "UNREFUTED + سطر الإثبات".
   - إن وجدت: اكتب "REFUTED + السطر + سيناريو الفشل".

3. GATE: لا يُشغَّل المحرك إلا وكل الادعاءات UNREFUTED بأرقام أسطر.
```

## متى يُستخدم (When to Use)
- كل ولادة محرك جديد — هذه بوابة إلزامية في [[Workflow - ولادة محرك جديد (قائمة الفحص)]].
- بعد أي تعديل يدوي على كود محرك يعمل (التعديلات اليدوية أخطر مصدر مفاجآت).
- قبل رفع أي سقف مخاطرة.

## مثال ناتج (Example Output)
- ادعاء «اللوت مسقوف بـ risk_cap»: REFUTED — سطر التعديل اليدوي `round(lot/0.01)*0.15` يضرب اللوت x15 بعد السقف ⇒ نُزع فتيله بـ config risk_cap 0.008.
- ادعاء «R Core لا يكدّس على الأحمر»: UNREFUTED — قاعدة no-stack-on-red موجودة ومفحوصة بالسطر.
