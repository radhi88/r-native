# Prompt - تشريح الصفقات (سبب الدخول وسبب الخسارة)

**Summary:** برومبت «تشريح جنائي» لكل صفقة: اربط سبب الدخول من فيد المحرك (JSONL) بالنتيجة الفعلية من طرفية MT5، ثم صنّف كل خسارة إلى: قتل فوري (<3 دقائق) / صيد ستوب (السعر رجع) / اتجاه خاطئ. [[high-value]] [[evergreen]]

## الغرض (Purpose)
المحرك يكتب لماذا دخل، والطرفية تكتب كيف انتهت الصفقة — لكن لا أحد يربط الاثنين تلقائياً. هذا البرومبت يصنع الربط، فيكشف هل المشكلة في **الفكرة** (اتجاه خاطئ) أم في **التنفيذ** (ستوب ضيق يُصطاد) أم في **التوقيت** (دخول لحظة سبريد/تقلب = قتل فوري). هذا هو الأسلوب الذي كشف أن AUDUSD مات خلال ثانيتين بستوب 1-pip = صيد ستوب مؤكد (انظر [[Decision - 2026-07-07 - جراحة عدم التماثل]]).

## نص البرومبت (The Prompt)
```
اعمل تشريحاً كاملاً لصفقات المحرك [ENGINE] (magic [MAGIC]) لآخر [N] يوم:

1. اقرأ فيد المحرك (data/r_native/*_feed.jsonl) واستخرج لكل صفقة:
   ticket/التوقيت/الاتجاه/سبب الدخول (entry reason) كما سجّله المحرك.
2. اتصل بـ MT5 اتصالاً واحداً (one-shot) واسحب history_deals_get
   للفترة نفسها، خذ صفقات الإغلاق فقط (entry==1)،
   واحسب pl = profit + commission + swap.
3. اربط كل سبب دخول بنتيجته (بالـ position id / magic / التوقيت).
4. صنّف كل خسارة إلى واحدة من ثلاث:
   - INSTANT-KILL: أُغلقت خلال < 3 دقائق من الفتح.
   - STOP-HUNT: ضرب الستوب ثم رجع السعر باتجاه الصفقة خلال N شموع.
   - WRONG-DIRECTION: السعر واصل ضد الصفقة (الفكرة نفسها خاطئة).
5. اعرض جدولاً: سبب الدخول × التصنيف × مجموع pl، ثم استنتاجاً واحداً
   قابلاً للتنفيذ (وسّع الستوب؟ فلتر سبريد؟ ألغِ الإشارة؟).
```

## متى يُستخدم (When to Use)
- بعد أي يوم أحمر لمحرك، وقبل أي «إصلاح» — الإصلاح بلا تشريح تخمين.
- قبل جلسة [[Workflow - محكمة السبورة (ترقية وتقاعد)]] لتفسير عمود payoff.
- عند الشك أن الستوب يُصطاد (STOP-HUNT عالٍ ⇒ أرضية ستوب = 3x سبريد).

## مثال ناتج (Example Output)
- multi-sentinel (magic 20260709): AUDUSD خسارة خلال ثانيتين بستوب 1-pip ⇒ STOP-HUNT مؤكد ⇒ قرار أرضية الستوب 3x سبريد.
- brain_trader: أسباب دخول متناقضة عبر 17 عملة بنتيجة coinflip ناقص السبريد ⇒ تقاعد (انظر [[Decision - 2026-07-06 - تقاعد الرشاش وولادة R Core]]).
