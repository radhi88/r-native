# Agent Bus — قناة استشارة بين وكيل VS و Claude (بدون تدخّل المستخدم)

> غرضها: وكيل VS يستشير Claude في كل خطوة، و Claude يرد بالمطلوب — تلقائياً عبر ملفات.
> المجلد: `C:\Users\Radhi\MT5\r_native_v2\agent_bus\`

## الملفات
| الملف | يكتبه | المعنى |
|---|---|---|
| `ASK.md` | **وكيل VS** | السؤال/المقترح/ما أنجزه ويريد رأياً فيه |
| `ASK.flag` | **وكيل VS** | يُنشأ بعد كتابة ASK.md = «سؤال جديد جاهز» |
| `REPLY.md` | **Claude** | الرد: المطلوب عمله / الموافقة / التصحيح |
| `REPLY.flag` | **Claude** | يُنشأ بعد كتابة REPLY.md = «الرد جاهز» |
| `LOG.md` | الاثنان | سجلّ تاريخي (append) لكل سؤال/رد |

## الدورة (handshake)
1. **وكيل VS:** يكتب سؤاله في `ASK.md` (استبدال كامل) ← ثم ينشئ `ASK.flag`.
2. **Claude:** مراقبه يصحّيه فور ظهور `ASK.flag` → يقرأ `ASK.md` → يكتب `REPLY.md` →
   يحذف `ASK.flag` → ينشئ `REPLY.flag` → يضيف للـ`LOG.md`.
3. **وكيل VS:** ينتظر ظهور `REPLY.flag` → يقرأ `REPLY.md` → ينفّذ → يحذف `REPLY.flag` →
   يكرّر من (1) للخطوة التالية.

## بروتوكول الكتابة في ASK.md (وكيل VS يلتزم به)
```
## السؤال / الخطوة
<ماذا تنوي تفعل أو ما الذي أنجزته وتريد رأياً فيه>

## السياق
<ملفات/مجلدات متأثّرة · مخاطر · بدائل>

## القرار المطلوب من Claude
<موافقة؟ تصحيح؟ تفاصيل تنفيذ؟ أولوية؟>
```

## 🔔 اتفاق الإشعار المتبادل (إلزامي — أُضيف 2026-06-06)
الهدف: كل طرف **يَعلم فوراً** أن الطرف الآخر أرسل، بلا تدخّل المستخدم.

**وكيل VS → Claude (عند سؤال):**
- يكتب `ASK.md` ← ينشئ `ASK.flag`. (مراقب Claude يلتقطه فوراً + Claude يفحص كل ٥ دقائق احتياطاً.)

**Claude → وكيل VS (عند رد):**
- يكتب `REPLY.md` ← ينشئ `REPLY.flag`.

**التزام وكيل VS (لكي «يُشعَر» بردّي):**
1. **في بداية كل دور:** افحص `REPLY.flag`؛ لو موجود → اقرأ `REPLY.md` ونفّذ ثم احذف `REPLY.flag`.
2. **بعد كتابة أي ASK:** ابقَ في حلقة فحص `REPLY.flag` **كل ٣–٥ ثواني** حتى يظهر — لا تتجمّد منتظراً المستخدم.
3. لا تفتح ASK جديد قبل قراءة REPLY السابق.

**التزام Claude:** مراقب حيّ على `ASK.flag` + فحص دوري كل ٥ دقائق (cron) → يرد دائماً ويُنشئ `REPLY.flag` + يسجّل في `LOG.md` + يُشعر المستخدم.

**كلاهما:** حدّث `HEARTBEAT_<اسمك>.txt` (ختم زمني) كل دورة لإثبات الحياة.

## 🟢 سياسة الصلاحيات (لا تُزعج المستخدم — أُضيف 2026-06-06)
المستخدم لا يريد أن يُسأل عن كل أمر. التزم:
- **أوامر روتينية آمنة** (read/cat/diff/md5/git status/git log/heartbeat/ls) → **شغّلها فوراً بلا سؤال.**
- **قرارات خطيرة فقط** (حذف/نقل/دمج/cutover/تعديل ملف حيّ/order_send) → **استشر Claude عبر ASK** (لا المستخدم).
- إن كان وضع تشغيلك يسأل المستخدم عن كل أمر: اطلب منه تفعيل auto-accept للأوامر الآمنة مرّة واحدة، ثم لا تسأله بعدها.

## قواعد ملزمة (الاثنان)
- **DEMO فقط · لا تكسر التداول الحيّ · لا تلمس magic 0.**
- وكيل VS **لا ينفّذ خطوة دمج كبيرة قبل ما يسأل Claude** ويأخذ REPLY.
- Claude يرد **عملياً ومحدّداً** (خطوات/ملفات)، وبنزاهة (لا حافة وهمية).
- كل خطوة **ذرّية وقابلة للرجوع** (commit صغير).
- لو Claude غير متصل (ما رد خلال مهلة يحدّدها VS)، وكيل VS **يقف ولا يدمج عشوائياً**.

## مثال
`ASK.md`: «أنوي دمج `fractal_strategy.py` من archive داخل `r_native_v2/strategies/`. متأثّر: chart_read. هل أمضي؟»
`REPLY.md` (Claude): «نعم لكن: (1) انسخ لا تنقل، (2) لفّه بـ try/except، (3) لا تربطه بالتداول قبل اختبار، (4) commit `merge: fractal_strategy (isolated)`. أرسل النتيجة قبل الربط.»
